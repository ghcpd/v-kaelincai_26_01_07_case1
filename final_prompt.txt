## Role & Objective

You are a senior software engineer responsible for analyzing, fixing, and comprehensively validating a flaky behavior bug in a scientific data analysis platform. Your complete objective is to:

1. **Analyze and identify** the root cause of non-deterministic behavior in the DataNormalizer implementation
2. **Create a complete fixed project** with deterministic source code, updated tests, and documentation
3. **Execute comprehensive validation** including environment setup, test execution, and verification
4. **Verify deterministic behavior** across multiple execution scenarios and hash seed variations
5. **Document all changes** and provide detailed validation summaries and results

## Inputs & Context

**Source Material:**
- Original buggy project: `issue_project/` directory containing:
  - `src/normalizer.py` (contains non-deterministic bug using unordered set)
  - `tests/test_normalizer.py` (flaky tests that fail intermittently)
  - `data/` folder with sample JSON/CSV files (sample_high_correlation.json, sample_high_correlation.csv, sample_low_correlation.json)
  - Supporting files: `requirements.txt`, `example_usage.py`, `README.md`, `KNOWN_ISSUE.md`

**Bug Description:**
- The `DataNormalizer` class exhibits flaky behavior: identical inputs produce varying outputs across runs
- Tests randomly pass or fail (not deterministic)
- Scores vary between runs (e.g., 6.87, 7.15, 7.23 for the same data)
- Root cause: Python's unordered `set` data structure for dimension names causes non-deterministic iteration order
- Non-determinism affects floating-point accumulation sequences and threshold-based logic decisions (particularly around the 0.85 correlation threshold)

**Working Directory:** Create project structure under workspace directory with `issue_project_fixed/` subdirectory

## Step-by-Step Instructions

### Phase 1: Project Analysis & Understanding
1. Examine the original `issue_project/` directory structure
2. Read and study `KNOWN_ISSUE.md` for detailed bug analysis
3. Analyze the buggy `src/normalizer.py` to identify the nondeterministic set iteration
4. Review `tests/test_normalizer.py` to understand the failing/flaky test cases
5. Understand the complete algorithm: Z-score normalization, correlation calculation, weighting strategy, and threshold logic

### Phase 2: Create Fixed Project Structure
1. Create complete directory structure: `<workspace>/issue_project_fixed/`
2. Create subdirectories:
   - `src/` (with `__init__.py`)
   - `tests/` (with `__init__.py`)
   - `data/`
3. Copy all data files from `issue_project/data/` to `issue_project_fixed/data/`:
   - sample_high_correlation.json
   - sample_high_correlation.csv
   - sample_low_correlation.json
   - README.md
4. Copy `requirements.txt` from original
5. Copy `example_usage.py` from original
6. Copy `KNOWN_ISSUE.md` from original

### Phase 3: Implement the Deterministic Fix
1. **Fix `src/normalizer.py` for determinism:**
   - Replace nondeterministic `set` iteration with deterministic ordered iteration (e.g., `list(data.columns)` or `sorted(list(data.columns))`)
   - Implement stable summation/vectorized operations for consistent floating-point calculation sequences
   - Eliminate all order-dependent logic in threshold decisions
   - Preserve exact algorithm logic: Z-score normalization, correlation calculation, weighting

2. **Verify API Preservation:**
   - Ensure public API remains identical (same method signatures, parameters, return types)
   - Algorithm produces identical results for identical inputs across all runs

3. **Update Tests in `tests/test_normalizer.py`:**
   - Remove flaky assertions that rely on nondeterministic behavior
   - Add deterministic assertions with specific expected values
   - Verify determinism consistency across runs
   - Ensure tests pass reliably without random failures

4. **Create Test Infrastructure if needed:**
   - Add `tests/conftest.py` for test configuration if required
   - Ensure proper Python path configuration for imports

### Phase 4: Documentation
